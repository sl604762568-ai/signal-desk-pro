# Signal Desk Pro v6.11 — 复盘优先、龙虎榜、自选、9:25竞价

这是完整的 FastAPI + 静态网页更新包。解压后，**上传文件夹里面的文件与 `static` 文件夹本身**到现有 `signal-desk-pro` GitHub 仓库根目录。文件夹不要套娃，不要上传 ZIP 本身。

## 本版已实现

1. **复盘优先排版**：收盘复盘、龙虎榜作为第二模块、独立9:25竞价、明日五股、自选、单股图形诊断、板块热度、AI复盘、技术历史股性、新闻，最后才是虚拟回测。顶部市场情绪保留，重复的独立“市场情绪与接力生态”版块隐藏；校验细节不在前端出现。
2. **复盘结果固定**：收盘15:00后第一次真实选股结果写入本地 SQLite `frozen_picks`，包含合法的空候选（完成扫描但未命中）。重复刷新只读取该交易日持久快照；次日盘前显示最近收盘的固定名单。手动重新生成端点必须提供管理员口令。
3. **异步板块复盘**：板块资金、板块成分另走异步任务；首个请求快速返回 `loading:true`，前端自动重试，失败有状态提示。三日轮动只用已经保存的真实收盘板块快照，没有足够历史时不编造轮动链。点击板块查询提供商的真实概念/行业成员关系。
4. **严格技术选股**：近30个交易日*各自至少一次*涨停、炸板、上影线超过前收4.99%、单日成交额超过50亿元；流通市值超过2.499亿元；当前最高价高于5日均线；最近3个交易日任一天换手率超过9.99%；主板 `00/60`、非ST、价格不超过80元，排除688/689。八项逻辑是严格 `AND`；涨停/炸板的历史判断基于真实前复权日K和前收的主板10%规则，极端除权日、新股无涨跌幅限制及分角分钱边界可能与逐笔专池口径不同，不应宣称100%精确。完整全市场行情预检及真实历史K数据不齐则报告状态，不能宣称全市场扫描完成。
5. **龙虎榜**：优先用东财公开龙虎榜日汇总获取上榜名单、上榜原因、已披露买卖额和净额。逐席位**未经验证**时，机构/游资/量化/北向资金净额不推断，不出现伪造的“机构共振/知名游资”数据；交易所披露的席位类别需要进一步可核验的专项接口或授权数据才能可靠分组。
6. **自选股**：使用腾讯逐股实时行情验证加入时价格与加入时间，保存模型触发时间字段、当日/累计涨幅、模型关注分（只有真实换手、量比、涨幅全部可用才计算）；点击自选股直接进入缠论可视化诊断。
7. **09:25竞价独立页**：仅在北京时间交易日09:25尝试采集，逐股验证行情提供方时间戳为09:25才归档，存库为单交易日快照；昨竞价、五日竞价均值来自各自历史真实快照，昨日完整成交额来自另行归档的真实15:00+日终快照。支持原指定门槛、流通市值动态竞价金额门槛、条件排序、只看自选竞价、自定义六维研究权重及按加权评分排序；六维数据不全不计算总分。题材聚合只对确实核验的公司概念与行业归属，新闻标题有明确题材匹配才链接，无出处不解释为事实。真实归档跨多个交易日后可以进行带**假设成交价**的描述性路径回测，非实际成交绩效。
8. **数据架构参照 `a-stock-data` 的公开多源直连原则**：本项目采用相应的腾讯少量股票报价与K线、东财仅用于完整快照、板块与龙虎榜的专项数据，交易所公开规则按现有模块使用。注意 `a-stock-data` 上游是 Markdown Skill + 可复用代码，不是直接 `pip install a-stock-data` 即可获得数据的商业接口。不同指标维持不同专门数据源，不拿小样本推全市场涨跌停。
9. **原来的单股图形分析、MACD、均线、缠论笔/中枢、手动/自动虚拟盘保留**。虚拟盘在导航及页面最后。

## 必须知道的限制

- **无法保证100%数据无误**：公共 API 会断线、限流，或存在不同统计口径。有冲突/缺失就让关键指标不可用，后台记录错误，不向用户发布猜测数值。交易所公开接口通常不提供可无限调用的免费逐笔实时交易服务。
- **Render Free不能保证9:25定时捕获**：服务器休眠就会错过。无法事后用盘中当日成交额代替最终竞价额，也不能用 `REF(DYNAINFO(15))` 当作历史竞价档案。
- **Render Free 的 `/tmp` SQLite 不持久**：休眠/重启/重新部署可能清除已冻结选股、自选、竞价归档、研究回测和虚拟交易记录。为了遵照目前“不接外部数据库”的要求，这一版维持SQLite；需要长期积累时**必须**迁移至持久化数据库或持久磁盘，不要把暂存结果当作永久历史。
- 龙虎榜汇总只保证已披露的**汇总口径**。机构席位、游资席位、量化类别、北向资金及真实资金主体并非一一映射，缺失即隐藏，不做错误归因。
- 技术和六维分数只代表可解释的模型观察，不是上涨概率，也不是实际交易决策。

## 安装、更新与测试

1. 下载 ZIP 并全部解压，进入解压后含 `app.py` 的目录，将全部文件及 `static` 一起上传至已有 GitHub `sl604762568-ai/signal-desk-pro` 根目录；提交更改，等待 Render 自动部署。无需新建仓库。
2. Render → `signal-desk-pro` → Environment，**自行生成**强口令添加 `CONTROL_TOKEN` 环境变量（例：自创16～32位不重复字符；这里不提供实际口令）。不要把任何口令提交 GitHub 或发给他人。自选添加/移除、启动完整历史股性扫描、手动采集竞价及计算竞价题材需要它；普通只读页面不需要口令。
3. 检查 `https://signal-desk-pro.onrender.com/api/health` 中 `version` 是否为 `6.11-auction-watchlist`；然后 `/api/dashboard`、`/api/sector-review`、`/api/dragon-tiger`、`/api/auction25`。竞价页面在未采集到真实9:25日档之前显示空白，这是符合要求的；不要用模拟数字填充。
4. 若板块复盘初次显示加载，等待后台独立任务完成后再次打开；若真实提供商超时，访问 `/api/sources` 和 Render Logs 查来源错误。校验诊断只放后端，前端不展示校验明细。
5. 可本地运行 `python test_v611_offline.py` 进行不连接外网的模块与API自动化测试；测试数据全部使用代码造的隔离夹具，**不会进入真实交易页面**。

## 便于排查的新API

- `GET /api/auction25`：支持 `trade_date`、`min_amount`、`min_boom`、`min_turnover`、`min_gap`、`max_gap`、`min_prev_day_pct`、`max_price`、`sort`。
- `POST /api/auction25/capture`：仅真实交易日上午09:25且需要 `X-Control-Token`。
- `GET /api/auction25/topics`，`POST /api/auction25/topics/analyze`（需口令），`GET /api/auction25/backtest`。
- `GET/POST/DELETE /api/watchlist`（写入需口令）。
- `POST /api/technical/scan`（需口令）、`GET /api/technical/results`。
- `GET /api/dragon-tiger`、`GET /api/sector-review`、`GET /api/health`。
