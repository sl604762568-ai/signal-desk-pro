# v6.12｜板块行情终端 + 真实单项/组合选股

以 v6.11.2 完整项目为基础，保留收盘复盘、龙虎榜、9:25 竞价、明日五股、单股多级别 K 线/缠论、原技术选股和虚拟盘。

## 新版入口

- **板块行情**：行业、概念、地域使用东方财富对应的真实板块列表；风格和热点是对真实概念板块的展示分组，组名不用于臆断股票归属。点击板块后，再按 `BKxxxx` 代码获取真正成分股，可切换当日涨幅、成交额、换手和主力净额排序；支持直接打开单股诊断。
- **资金**：展示当日、5 日和 10 日板块主力净额（供应商资金流估算口径），并显示板块涨跌、真实上涨成员占比及横截面板块热度参考。资金净额无法反映准确的具体机构身份或保证后续走势。
- **三日轮动**：仅显示本地数据库真实已采集的最近 3 个交易日板块快照；记录少时明确显示不足 3 日，不能编造历史。历史快照如果是在盘中生成，应按盘中快照理解。
- **单项/组合筛选**：价格上下限、涨幅上下限、成交额上下限（本版界面为最低额）、真实缓存的流通市值上下限、量比、换手率、MA5/10、1 分钟涨跌速度、10 分钟振幅、连续 3 个已完成采样区间放量、涨幅>5%非新股（上市日期必须验证）。一个参数是单项，多个非空参数同时勾选是 AND 组合。提供 1 分钟涨速、涨幅、成交额、量比、换手、10 分钟振幅排序。点击结果可进入原单股分析。

## 精确性与性能说明

1. **不使用演示行情做新增模块**。全A行情源无法返回时，手动输入代码可独立尝试腾讯批量行情；缺失指标显示 `--`，勾选条件时未验证的样本不通过。
2. **1 分钟/10 分钟只针对真实连续采集的监控池**，最多 160 只。当前监控池默认来自实时快照的 `review_universe/active_stocks`，绝不把它的排名称为“全A排名”。
3. 只在中国交易时间采集带有效行情时间戳的腾讯快照；1 分钟至少需要前后约 1 分钟的两个快照；10 分钟振幅需要跨度约 10 分钟且至少 7 次采样；连续放量需要 4 个相邻快照。如果错过任何时间窗显示未验证。
4. 免费 Render 可能休眠、重启并丢失运行内存与临时 SQLite 文件；这会中断分钟连续性、三日轮动与旧虚拟盘记录。需要持续监控/持久保存，请采用持久数据库及具备调度保证的服务，不能仅依赖打开网页。
5. 按需刷新并保持旧首页快速展示：板块分类独立后台加载；分钟监控仅在用户点击或主动勾选每 60 秒刷新后执行；打开其他模块不强制同时抓取所有板块及 K 线。MA5/10 仅对当前池前 20 只按需获取历史 K 线，且不把 20 只覆盖说成全市场验证。
6. 行情可能延迟，非新股判定需从东财单股公开 `f26` 取得并验证上市日期；取不到时该条件不通过。百分比、主力资金净流入等字段遵循数据供应商自身口径。源异常或不同平台口径差异时不得用模型估计伪装成权威统计。

### 开源来源

本版使用现有项目中的腾讯批量报价与东方财富公开板块数据适配器，并参考 [a-stock-data](https://github.com/simonlin1212/a-stock-data) 的多源优先级思路；**没有把该仓库的整个 Skill/全部端点复制或安装成运行时依赖**。同花顺官方 iFinD 接口如需精确龙虎榜/板块增量数据，可能需要对应许可和凭证，未授权时不伪称已经接入。

## 部署

1. 解压整个 ZIP，根目录的 `app.py`、`terminal_explorer.py`、`sector_engine.py`、`public_sources.py`、`requirements.txt`、`render.yaml` 和 `static/` 应处于同一级。
2. 用 GitHub Desktop 克隆已有仓库，将解压文件复制覆盖至仓库根目录，Commit 后 Push 到原仓库。无需新建服务。
3. Render 部署成功后访问 `/api/health`，应返回 `6.12-sector-factor-terminal`。再用 `/api/boards/explorer/groups` 测试新版路由，最后打开首页的「板块行情」标签。
4. 如仍有问题，从 Render Logs 查上游请求超时；先确保已有模块运行正常，再单独测试板块分类和手动输入代码的单项筛选。

本地静态/接口测试只能证明代码与路由可运行；不能证明部署后第三方公开源在 Render 所在区域可访问。
